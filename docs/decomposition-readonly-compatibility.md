## Что делает новая проверка

deploy/decomposition_compatibility_audit.py читает только семь разрешённых файлов:
пять файлов будущего изменения и два существующих маршрутизатора. Она разбирает
Python через ast, не импортирует приложение и не открывает базы/секреты.

Для двух существующих файлов предлагаются изменения **только в памяти**:

- В main файла запуска добавить import/install decomposition_trainer после
  middle_salts_trainer.install() и до установки публичного маршрутизатора.
- В цикле _trainer_goals исключить code == decomposition перед выбором таблицы,
  не меняя прочие месячные условия.

Проверяется уникальность/порядок опорных мест; после удаления предложенных вставок
AST должен совпасть с исходным. Тесты дополнительно проверяют сохранение каждого
остального символа, серверных дополнений и переводов строк. Неоднозначная структура,
уже подключённый модуль, изменённая сигнатура, симлинк, ошибка синтаксиса или наличие
любого из трёх новых файлов приводят к остановке/блокировке для разбора.

В отчёте только фиксированные имена файлов, SHA-256, булевы признаки и статусы.
Исходники, названия частных функций и значения констант на GitHub не передаются.
Восемь локальных тестов прошли; вставки также рассчитаны на одноразовых копиях
двух публичных файлов из main. Это не проверка фактической структуры VPS.

Положительный результат означает только INSERTIONS_POSSIBLE_ROUTING_BEHAVIOR_STILL_UNVERIFIED.
Сигнатуры update/context не доказывают эквивалентность серверных обработчиков:
routing_behavior_verified и approved_for_release всегда false.
Совпадение всех нужных функций и полный запуск бота остаются отдельной проверкой.

## Как запускается без публикации тренажёра

Это отдельный диагностический PR на базе main. Он не содержит файлов тренажёра,
не меняет run_bot_production.py/kulek_rewards.py, не сливает PR #64 и не устанавливает
ничего на VPS. Слияние этого диагностического PR создаёт явно названный intent и
запускает workflow с проверкой; до SSH требуется отдельное одобрение защищённого
окружения ege-lab-production в GitHub. Возможен также ручной workflow_dispatch на main.

В PR выполняются только локальные тесты: у PR и feature-веток нет SSH-job и доступа
к секретам. Remote-job разрешён только на main, после локальных тестов, с прежним
ограниченным пользователем ege-deploy, закреплённым ключом хоста и защищённой средой.
Никаких scp, sudo, systemctl restart, git pull/reset, записи кода/БД на VPS нет.

Используется уже существующая SSH-команда python3 - --mode remote. Если серверный
ограничитель отвергнет новый диагностический скрипт, проверка остановится; никаких
попыток расширить права или сменить ключ/пользователя автоматически не будет.

## Граница будущего выпуска

Копировать два GitHub-файла целиком поверх VPS по-прежнему нельзя. Старый офлайн-комплект
из PR #64 остаётся проверкой эталонных GitHub-копий. Настоящий выпуск должен привязать
точечные вставки к свежим хешам серверных файлов и заново рассчитанным итоговым хешам;
предложенный минимальный guard Кулёчков отличается текстом от эталонного варианта PR #64.
Нужны отдельная сверка поведения маршрутизаторов, согласованный backup, installer,
проверка отката и явное разрешение публикации. Этот диагностический PR такого разрешения
не даёт и не содержит механизма обновления приложения.
