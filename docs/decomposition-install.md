# Установка разложения — отдельное разрешение владельца получено

Владелец прямо попросил установить тренажёр. Это разрешение на точечный выпуск;
оно не разрешает заменять серверную версию файлами из GitHub целиком.

## Комплект

Три новых файла берутся по неизменяемому commit f8eeb92d7e1ecbaed9a1a46c7673125dae3512b6
и индивидуальным SHA-256. В entrypoint и kulek_rewards.py — только две вставки
с проверенными исходными и итоговыми хешами. Сверяются также оба серверных
маршрутизатора. Любой дрейф или коллизия останавливает выпуск.
Месячные условия Кулёчков decomposition не пополняет.

## Разовая настройка доступа

Действующий ege-deploy не имеет права устанавливать новый комплект.
bootstrap_decomposition_release.sh из точного проверенного коммита запускается
один раз в root-консоли. Он проверяет хеш установщика, ставит root-owned helper
и разрешает ege-deploy ровно две команды: установка и откат этого выпуска.
Ключи/пароли/существующие SSH-ограничители не меняются. Тренажёр и БД на этапе
настройки не меняются, сервис не перезапускается.

## Установка

Только ручной decomposition-controlled-release.yml на main с operation=install,
от владельца и с допуском ege-lab-production. Нет deploy по push/merge.
Workflow не загружает и не исполняет произвольные CI-скрипты как root:
он вызывает заранее установленный root-owned helper.

Helper требует root, фиксированный идентификатор, активный ege-bot и общий
серверный lock с лабораторией. Он не выполняет git pull/reset/checkout.
Путь SQLite должен быть явно подтверждён runtime-vars.json или Environment
службы и совпасть с data/coreapp_webhooks.db. При неоднозначности — остановка.
Конфигурация и приватные логи никуда не выгружаются.

Перед записью: защищённая копия двух исходников с UID/GID/правами и online backup
SQLite через backup API, включая committed WAL; integrity_check копии.
После повторной сверки хешей пять файлов пишутся атомарно с исходными правами
для изменяемых и 0644 для новых. Включается только публичная видимость decomposition.
Перезапускается только ege-blizko.

Проверяются health, активность, маркер загрузки 50 вопросов, новые таблицы
и точная запись реестра. Это startup-проверка, не подтверждение мобильного UI
или всех сценариев реального Telegram. После успеха нужно открыть
/start decomposition и каталог в действующем боте.
Автоматических анонсов или сообщений ученикам этот выпуск не добавляет.

## Откат

При ошибке записи/запуска/health прежний код возвращается автоматически,
новые три файла удаляются, оба каталожных флага decomposition выключаются.
БД НЕ заменяется старой копией: новые оплаты, ответы и ДЗ сохраняются.
Новые таблицы не удаляются.

После успешной установки доступен тот же защищённый workflow с operation=rollback.
Он проверяет, что все пять файлов ещё принадлежат этому выпуску, восстанавливает
два оригинала с UID/GID/правами, убирает новые файлы, выключает оба флага и
перезапускает сервис. Дрейф после выпуска не затирается.
Backup и last-success: /var/lib/ege-blizko-decomposition.

## Проверки

9 синтетических тестов: атомарная запись и отказ после rename, сохранение прав,
WAL backup, отсутствие потери последующих оплат, оба флага, успех/провал health,
автоматический и ручной откат. Точные патчи дополнительно рассчитаны на полученной
закрытой копии VPS и совпали с хешами прежнего аудита; три payload-хеша проверены.
Реальной установки до защищённого запуска не было.
