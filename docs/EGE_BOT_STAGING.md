# ЕГЭ БЛИЗКО — первая изолированная тестовая копия

## Что готово

`.github/workflows/ege-bot-offline-staging.yml` создаёт **одноразовую офлайн-копию только публичного кода GitHub** во временной папке GitHub Actions. Скрипт `deploy/ege-bot-offline-sandbox.py` статически обходит импорты начиная с `run_bot_production.py` и `ege_lab_webapp.py`, копирует связанные Python-файлы, формирует отчёт `preflight.json` и создаёт **отдельную синтетическую** базу `fixtures/synthetic-only.sqlite` с вымышленной записью.

Это проверка изоляции и подготовка тестового окружения, **НЕ запуск работающего Telegram-бота**. Тесты подтверждают, что даже при наличии в checkout `.env`, настоящих SQLite/JSON-файлов и кода соседних продуктов они не копируются и не исполняются. Код приложения не импортируется.

Сценарий не имеет разрешений на изменение репозитория, не использует секреты GitHub и не подключается к VPS, Telegram, ПРЕПОДМИНУ или LMS.

## Почему пока нельзя сделать полнофункциональный стенд из main

Сверки [контрольных сумм](https://github.com/mariyasedova08-beep/ege-blizko-timer-bot/actions/runs/39745394232), [структуры](https://github.com/mariyasedova08-beep/ege-blizko-timer-bot/actions/runs/39751748449) и [закрытая инвентаризация](https://github.com/mariyasedova08-beep/ege-blizko-timer-bot/actions/runs/39770956980) показали, что рабочая версия VPS отличается от GitHub, включая 23 связанных Python-модуля, отсутствующих в корне GitHub. Поэтому запуск `run_bot_production.main()` из checkout без предварительного переноса/проверки зависимостей недопустим. Скрипт **всегда** маркирует результат как `PREPARATION_ONLY_NOT_READY_TO_RUN_BOT` и не выполняет приложение.

Синтетическая БД — не копия реальной схемы учащихся и не способ проверить фактические миграции. Статический обход импортов также не гарантирует обнаружения динамических загрузок.

## Что нужно для рабочего тестового бота

1. Подготовить закрытую, зашифрованную и проверенную резервную копию серверной версии **вне публичного репозитория**; не копировать базы учащихся, ключи или `.env` в GitHub.
2. Согласовать приватное хранилище и изолированный тестовый компьютер/контейнер с отдельными разрешениями, отдельной синтетической БД и **отдельным тестовым Telegram-токеном**. Реальный токен не использовать.
3. На тестовом окружении восстановить необходимые серверные модули и JSON-банки, проверить зависимости и права, не исполняя init/seed против production.
4. Добавить интеграционные тесты тренажёров, восстановления попыток, Кулёчков, уведомлений и лаборатории. Все внешние сообщения должны уходить только в заглушки или тестовые чаты.
5. После тестов сделать план точечного выпуска с бэкапом и проверкой отката. **Любой выпуск — только после отдельного подтверждения владельца.**

## Запреты

Нет автоматического `git pull/reset/checkout` в `/opt/bots/ege-blizko`, нет публикации исходников VPS в публичный GitHub, нет деплоя по push/merge, нет использования рабочих данных учеников. ПРЕПОДМИН, LMS и медицинский бот — не цели этого проекта.
