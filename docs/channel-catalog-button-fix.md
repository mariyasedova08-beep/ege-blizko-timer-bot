# Исправление кнопки «Подписчики канала»

## Подтверждённая причина

22.10.2026 на VPS журнал подтвердил:
`TypeError: _bridge_catalog.<locals>.public_rows() got an unexpected keyword argument 'assigned_only'`.
Обработчик `cab:channeltrainers` вызывает статистику, которая передаёт
`assigned_only=True` в каталог. VPS-only модуль `oge_classification_trainer.py`
подменяет каталог адаптером с несовместимой сигнатурой.

Полный модуль не публикуется: его нет в GitHub, он получен закрытым снимком VPS.
Исправление меняет только начало вложенной функции в `_bridge_catalog`:

```python
    def public_rows(include_hidden=False, assigned_only=False):
        rows = list(original_rows(include_hidden=include_hidden, assigned_only=assigned_only))
        if assigned_only:
            return rows
```

Далее исходный код добавления публичного ОГЭ остаётся побайтно прежним.
Таким образом `assigned_only` передаётся исходному каталогу, а публичный ОГЭ
не добавляется к назначенным темам 11 класса. Публичный и административный
каталоги сохраняют видимость ОГЭ, настройки скрытия и защиту от дублей.

## Границы выпуска

Единственный изменяемый runtime-файл:
`/opt/bots/ege-blizko/oge_classification_trainer.py`.

Входной SHA256: `0d8a8c2133c2fa611f9ce60cbcea32698d92a7746b2e2e3a71b815cadd3c0a08`.
Выходной SHA256: `bf47b1f261be1e45e1275debee376c557a7db237a1b3f02b0c9ed3ba7377d00c`.
Также проверяется неизменность `public_channel_trainers.py`:
`be7b8d058da8cfd90ed57f9dae1f9e7769b448763ef56a8a18bdbebeab8c9a53`.

Сверяются полный файл и AST-контекст правки. Другие версии отклоняются.
Ни база, ни результаты, ни оплаты, ни расписания, ни файлы разложения не меняются.
Резервная копия только исходного Python-файла и метаданных создаётся в
`/var/lib/ege-blizko-channel-catalog-20261022`, права 0700/0600.
Запись атомарная, с сохранением uid/gid/mode и fsync.
Установщик использует общий lock выпуска, перезапускает только `ege-blizko`,
проверяет active и localhost `/health`; при сбое восстанавливает исходный файл.
Повтор после успешной установки не перезапускает бот.
Если незавершённая подготовка оставила каталог backup, повтор останавливается:
состояние нужно проверить, резервную копию автоматически не перезаписывать.

## Одноразовое подключение и публикация

Bootstrap устанавливает root-owned helper и sudoers только для двух буквальных
действий install/rollback. Он не меняет runtime, authorized_keys и не перезапускает бот.
Вызывать bootstrap следует по SHA коммита после проверки SHA256 самого bootstrap.
Это отдельная настройка права, а не разрешение произвольной root-команды.

После отдельного согласия на исправление: merge проверенного PR, затем workflow
`channel-catalog-controlled-release.yml`, main, operation=install. Ручной gate
`ege-lab-production` обязателен. Запуска по push/merge нет. Учётная запись ege-deploy,
доверенный хост и защищённые TIMEWEB_* секреты повторно используются.
GitHub подключение не поддерживает dispatch и одобрение среды: эти действия выполняет владелец.

Успех сервера: `CHANNEL_CATALOG_PATCH_OK_BACKUP_AND_HEALTH_VERIFIED`.
Это не подтверждение UI. После выпуска владелец должен нажать:

1. Кабинет → Тренажёры → Подписчики канала: текст статистики, без TypeError.
2. Назад и повторное открытие: без повторной ошибки.
3. Каталог для канала: ОГЭ виден согласно своим настройкам.
4. Назначенные темы 11 класса: публичный ОГЭ не добавлен.
5. `/start decomposition`: установленный тренажёр продолжает открываться.

Ручной откат: тот же workflow, operation=rollback. Требует точного выходного хеша,
восстанавливает original.py и метаданные, перезапускает и проверяет health.
База данных при откате не восстанавливается и не изменяется.

## Проверки до публикации

12 unittest-проверок: воспроизведение исходной ошибки; четыре комбинации
include_hidden/assigned_only; скрытый ОГЭ; повторы без дублей; идемпотентность;
сохранение всех остальных байтов; отказ при неизвестном коде; полный цикл
установки/отката на временных файлах; автоматический откат при failed health;
отказ при изменённом файле; повтор без restart; отказ для симлинка.
Отдельно преобразование проверено на полном закрытом снимке VPS и совпало с
обоими заявленными хешами; код приложения при этом не импортировался.
Реальный перезапуск и кнопки до выпуска не проверены.
