# Передача закрытой копии маршрутизаторов — подготовка, не публикация

Этот отдельный PR не содержит тренажёра и не сливает PR #64.
В production не устанавливается ни один файл, приложение и БД не открываются.
В PR выполняются только 12 локальных тестов без секретов и SSH.

## Механизм

- Только ручной workflow_dispatch на main от mariyasedova08-beep.
  Push и merge не запускают чтение VPS.
- Перед защищённым job требуется отметить, что получатель уже проверил
  расшифровку синтетического CMS своим закрытым ключом вне публичных логов.
  Это заявление оператора, а не автоматическое доказательство владения ключом.
  При отсутствии проверенного ключа реальную копию не запускать.
- Затем требуется ручное одобрение существующего окружения ege-lab-production.
- Используются прежние TIMEWEB_* настройки: только ege-deploy и закреплённый
  SSH-хост. Проверка ключа хоста обязательна; получения новых ключей нет.
- Перед чтением проверяются хеш сертификата, его действительность по времени
  и точный SHA-256 скрипта упаковки.
- Единственная SSH-команда: python3 - --mode remote. Если серверный ограничитель
  не допускает этот скрипт, операция завершается; права не расширяются.
- Переданный скрипт читает только два модуля с зафиксированными хешами:
  run_bot_live7.py и public_channel_trainers.py. Любое отличие блокирует копию.
- Исходники шифруются в памяти на VPS: CMS AES-256-GCM. Никаких временных
  исходников, архивов или новых файлов на VPS не создаётся.
- Контроллер проверяет формат CMS без расшифровки и сохраняет только шифротекст
  с правами 0600. GitHub artifact хранится один день. Текст ошибок удалён
  из публичных сообщений; исключения и stderr SSH/OpenSSL не печатаются.

Базы, .env и прочие файлы не читаются. При этом шифрование сохраняет точный
Python-код, включая любые встроенные константы: не расшифровывать его в
публичном job/логе и не публиковать как исходник в этом репозитории.

## Проверено локально

12 тестов на вымышленных файлах и одноразовом RSA-ключе: точный состав и хеши,
неисполнение приложения, сохранение остальных файлов, отказ при дрейфе,
симлинках, гонке чтения, неправильном размере/типе/синтаксисе, неправильном
сертификате/скрипте, сбое/таймауте SSH и неправильном CMS.
Проверены реальные шифрование/расшифровка и отказ при повреждении GCM-тега;
транспорт в тестах заменён, настоящее SSH-подключение не выполнялось.

## Что этот PR не подтверждает

Не проверены допуск скрипта ограничителем VPS, получение реальной копии,
доступность закрытого ключа получателю и фактическая расшифровка.
Полного тестового бота здесь нет; два файла не заменяют все зависимости.
Поведение серверного каталога, deep link и статистики ещё не проверено.

После получения копии нужен закрытый изолированный разбор с синтетическими
данными и заблокированными внешними обращениями; импортировать эти файлы
прямо на VPS для проверки нельзя.

Слияние этого отдельного PR само по себе не разрешает ручную передачу,
слияние PR #64 или деплой тренажёра.
