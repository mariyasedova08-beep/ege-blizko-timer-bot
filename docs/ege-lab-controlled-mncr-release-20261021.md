## Новый механизм в этом PR

1. **На PR:** выполняется только статическая проверка `bash -n` и тесты защитной логики. Никакого SSH, токенов или публикации.
2. **Выпуск запускается только:** после отдельной команды владельца и коммита в `main` файла `deploy/release-intents/ege-lab-mncr.txt` с **строго тремя фиксированными строками** (release ID, stage commit, проверенный SHA-256).
3. **В GitHub:** workflow требует автора `mariyasedova08-beep`, ветку `main`, успешную защитную проверку и окружение `production-lab`.
4. **На Timeweb:** через защищённый SSH-канал выполняется `deploy/ege-lab-mncr-approved-release.sh`. Он проверяет Git, наличие неизменённого билда, ожидаемое состояние автообновления, делает свежий аварийный бэкап SQLite и кода, удерживает *тот же flock*, что и legacy autodeploy.
5. **Изменяет только четыре лабораторных модуля**: `ege_lab_webapp.py`, `ege_lab_substances.py`, `ege_lab_inorganic_reactions.py`, `ege_lab_mn_cr_pdf_import.py`. **Никогда не подменяет** `public_channel_trainers.py`, `run_bot_production.py`, боты ПРЕПАДМИН, независимую LMS, токены и ученические SQLite.
6. **После выпуска** проверяет запуск `ege-blizko`, HTTP /health, SHA нового лабораторного интерфейса и неизменность двух защищённых локальных файлов. При ошибке восстанавливает прежние четыре файла и перезапускает только эту службу. Резервную SQLite сохраняет, но **не откатывает ученические данные** автоматически.

## Обязательная однократная настройка — ещё НЕ выполнена

Чтобы workflow реально получил доступ к Timeweb, нужно **однократно** настроить GitHub; без этого он будет отказывать в запуске, а не угадывать секреты:

- Перенести этот **отдельный инфраструктурный PR** в `main` только после ревью. Это не публикует лабораторию: файла release-intent здесь НЕТ.
- В `Settings → Environments` создать `production-lab`, включить **Required reviewers** (владелец репозитория) и ограничить ветки до `main`.
- Безопасно создать отдельный SSH-ключ деплоя с минимально необходимым доступом к Timeweb. В GitHub **environment secrets** настроить `EGE_LAB_DEPLOY_SSH_KEY` и `EGE_LAB_DEPLOY_KNOWN_HOSTS` (проверенный по независимому каналу SSH host key). **Никогда не писать закрытый ключ, пароль или .env в чат**.
- Текущий скрипт использует `root@77.233.212.200`, поскольку работает со службами и каталогом `/opt/bots`; рекомендовано заменить на узкого пользователя `ege-lab-deploy` с ограниченными привилегиями, **до передачи секретов**. Использовать root-ключ допускается только после отдельного явного согласования рисков.
- Проверить GitHub environment protection settings: наличие самого `environment:` в YAML **не** обеспечивает ручное одобрение, пока required reviewers не включены.
- Установить сеть/доступ с GitHub hosted runner на SSH сервер Timeweb; никаких сетевых допущений до проверки.

## Как будет выглядеть публикация

После завершения однократной настройки владелец пишет в чате «публикуем лабораторию Mn/Cr».
Ассистент ещё раз проверяет GitHub-проверки и текущие пины, только после явного согласия создаёт release-intent в `main`.
Workflow становится доступен к запуску и будет ждать явного одобрения окружения `production-lab` в GitHub. Далее SSH, preflight, fresh backup, четыре целевых модуля, health, откат при ошибке — автоматически.

**Нельзя писать «публикуем» раньше настройки SSH/окружения.** В текущем состоянии выпуск заблокирован специально.
