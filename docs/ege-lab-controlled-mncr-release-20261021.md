4. **На Timeweb:** через защищённый SSH-канал выполняется `deploy/ege-lab-mncr-approved-release.sh`. Он проверяет Git, наличие неизменённого билда, ожидаемое состояние автообновления, делает свежий аварийный бэкап SQLite и кода, удерживает *тот же flock*, что и legacy autodeploy.

- Безопасно создать отдельный SSH-ключ деплоя с минимально необходимым доступом к Timeweb. В GitHub **environment secrets** настроить `EGE_LAB_DEPLOY_SSH_KEY` и `EGE_LAB_DEPLOY_KNOWN_HOSTS` (проверенный по независимому каналу SSH host key). **Никогда не писать закрытый ключ, пароль или .env в чат**.

Скрипт использует `sudo` с разрешением ровно на один root-owned релизный файл и один фиксированный release ID; интерактивный root-доступ GitHub не передаётся.

- Установить сеть/доступ с GitHub hosted runner на SSH сервер Timeweb; никаких сетевых допущений до проверки.
- При следующих изменениях лаборатории пины SHA и точный staging пакет должны обновляться с новой химической и браузерной регрессией.

## Настройка ограниченного SSH-пользователя на Timeweb (однократно)

На сервере, в **серийной консоли root**, запускается заранее проверенный `deploy/bootstrap-ege-lab-deploy.sh` **по точному SHA коммита**, не по изменяемой ссылке ветки. Скрипт сам запросит одну строку ПУБЛИЧНОГО ключа `ssh-ed25519 ...` из PuTTYgen. Это не private key. Он проверит ключ, создаст системного пользователя `ege-lab-deploy` без пароля, ограничит его `authorized_keys` до одной forced-команды, установит root-owned pinned script и ограниченный `sudoers`. Действующий `ege-blizko` не останавливается. При любой ошибке предвалидации аккаунт не создаётся.

**НЕ вводить приватный ключ в Timeweb, терминал, чат или публичные файлы GitHub.** Приватный OpenSSH-ключ затем вручную добавляется в `production-lab` environment secret `EGE_LAB_DEPLOY_SSH_KEY`.

Второй secret `EGE_LAB_DEPLOY_KNOWN_HOSTS` — *публичный SSH host key* Timeweb; его нужно получить и сверить с независимым отображением на самом сервере, а не слепо принимать из сети.

Если секреты ещё не заданы, GitHub завершит шаг с ошибкой ДО сетевого обращения к серверу. При отсутствующих forced command/sudoers серверный релиз немедленно откажет.
