# Доступ к тестовой лаборатории: первая фаза

Эта настройка даёт отдельной учётной записи ege-lab-inspect только фиксированный отчёт о тестовом каталоге /home/maria-admin/lab-test-20261028 и HTTP-статус страницы на 127.0.0.1:8767. Отчёт содержит размеры и SHA-256 выбранных Python-файлов, без исходников и секретов. Код лаборатории не импортируется.

Это диагностический доступ. Он не устанавливает сборки, не запускает команды разработки и не выполняет production-развёртывание. Для обновления тестового приложения потребуется отдельный проверенный механизм. Не следует объявлять эту фазу полноценной настройкой автономного развёртывания.

Установщик запускается один раз из доверенной root-консоли. Он не редактирует существующие ege-deploy/ege-lab-deploy, настройки sshd, firewall, nginx, бот, базы или сервисы. Новые пути:

- /var/lib/ege-lab-inspect — новая учётная запись, root-owned home и authorized_keys.
- /usr/local/libexec/ege-lab-test-ssh — разрешает только точную команду lab-test-status-v1.
- /usr/local/libexec/ege-lab-test-inspect.py — фиксированная диагностика от имени maria-admin.
- /etc/sudoers.d/ege-lab-test-inspect — только этот helper, только от maria-admin, без аргументов; нет прав root.
- /root/.ssh/ege_lab_test_actions — новый приватный ключ, выводится только путь. Ключ не отправлять в чат или репозиторий.

Ключ имеет restrict и принудительную команду: нет интерактивной оболочки, PTY и перенаправления портов. Установщик отказывается перезаписывать отличающиеся существующие файлы. Существующие SSH-ключи и production-правила не изменяются.

После успешной установки нужно в GitHub создать окружение lab-test и два environment secret:

- LAB_TEST_SSH_KEY — содержимое нового приватного ключа, только в защищённое поле GitHub.
- LAB_TEST_KNOWN_HOSTS — точная строка `77.233.212.200 ssh-ed25519 PUBLIC_HOST_KEY`, полученная из /etc/ssh/ssh_host_ed25519_key.pub через доверенную Timeweb-консоль. Не получать доверие через непроверенный ssh-keyscan.

Environment secrets не копируются из production. Workflow .github/workflows/ege-lab-test-inspect.yml подключается именно как ege-lab-inspect и делает только фиксированную проверку. Первый запуск по push может завершиться до заполнения secrets; после настройки его нужно повторить. Workflow проверяет имя хоста, тип ключа и закреплённый ключ хоста. Изменение workflow в feature-ветке не означает его появление в списке ручного запуска default-ветки.

Отключение доступа: из root-консоли переименовать только /var/lib/ege-lab-inspect/.ssh/authorized_keys в резервный файл, затем удалить только LAB_TEST_SSH_KEY из окружения lab-test в GitHub. Это сохраняет все ранее действовавшие подключения. Удалять существующие production-учётные записи или перезапускать SSH не требуется.
