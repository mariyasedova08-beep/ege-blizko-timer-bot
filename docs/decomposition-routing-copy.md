# Закрытая копия для проверки маршрутизации: подготовка без запуска VPS

Цель — получить два фактических модуля для изолированного разбора входа
decomposition, каталога и публичной статистики. Это не полный стенд и не релиз.

## Подготовлено

deploy/seal_decomposition_routing_copy.py не содержит SSH, installer, импорта
бота, обращения к БД или команд сервисов. Он читает только run_bot_live7.py и
public_channel_trainers.py. Хеши зафиксированы по защищённой диагностике
39810060521 от 22.10.2026, 19:24 МСК. Любое отличие требует новой проверки,
автоматического обновления ожидаемых хешей нет.

Каталоги открываются через дескрипторы с O_NOFOLLOW; симлинки в пути,
необычные типы файлов, превышение размера, изменение во время чтения,
ошибка синтаксиса и несовпадение хеша останавливают подготовку.
Приложение не исполняется. Другие файлы, включая .env и SQLite/WAL, не читаются.

JSON с точными исходными байтами и SHA-256 существует только в памяти,
затем шифруется OpenSSL CMS AES-256-GCM для уже закреплённого сертификата
deploy/sealed-audit-public-cert.crt. Сертификат сверяется по SHA-256:
fe1f46e8f15ae494bef7280ab5491bf3a243a9e5c7c124bbc294bdf462754d6b.
Записывается только шифротекст, новым файлом с правами 0600, без перезаписи.
При ошибках выводится фиксированное сообщение без исходников/трассировки.

Шифрование не удаляет возможные встроенные в Python константы и данные.
Копия должна оставаться закрытой; её нельзя расшифровывать в публичных логах
или коммитить в этот публичный репозиторий. Сканер секретов не заявляется.

## Что проверено

Восемь локальных тестов на вымышленных файлах: фиксированный состав,
отсутствие исполнения, отказ при дрейфе/исчезновении/подмене симлинком,
неправильном размере/типе/синтаксисе, изменении во время чтения,
чужом сертификате и сбое OpenSSL; сохранность существующего результата.
Реальная криптографическая проверка использует одноразовый тестовый RSA-ключ:
зашифрованный пакет восстанавливается побайтно, изменение GCM-тега отвергается.

## Следующие обязательные условия — пока не выполнены

1. Проверить владение закрытым ключом закреплённого получателя на синтетическом
   зашифрованном пакете в закрытом окружении. Не просить ключ в чате.
2. Подготовить отдельный контроллер передачи, проверку срока сертификата,
   ограничение SSH-команды и защищённый workflow на доверенной main. Наличие
   этого скрипта в feature-ветке не разрешает передавать его на VPS.
3. Заранее определить закрытое место расшифровки и срок хранения. В GitHub
   допустим только шифротекст с коротким сроком хранения; исходники не логировать.
4. После защищённого одобрения выполнить только чтение, сверить свежие хеши,
   получить копию; не выполнять код на VPS и не перезапускать приложение.
5. Проверить расшифрованные модули в изоляции без production-токена, сети,
   данных учеников и рассылок. Оба файла сами по себе не дают полного запуска:
   оставшиеся серверные зависимости и конфигурация ещё не перенесены.

Этот этап не подтверждает поведение серверных маршрутизаторов. Скрипт на VPS
не запускался, реальный код не копировался, рабочие файлы не менялись.
PR #64 остаётся draft. Слияние и публикация тренажёра не разрешены.
