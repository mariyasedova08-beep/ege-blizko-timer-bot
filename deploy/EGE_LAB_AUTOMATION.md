# ЕГЭ БЛИЗКО — защищённый выпуск обновлений лаборатории

**Статус:** инфраструктура подготовлена в GitHub; действующий сервер не изменён.

## Принцип

1. Изменения разрабатываются отдельно, проходят автоматические проверки каталога 195 веществ / 435 реакций и JS/Python.
2. Публикация НЕ запускается от обычного push/PR. Только ручной `workflow_dispatch` на `main`, где указывается полный SHA текущего `release/ege-lab` и явный выбор `DEPLOY_LAB_ONLY`.
3. GitHub проверяет, что SHA соответствует вершине разрешённой ветки и для него есть успешная изолированная CI-проверка.
4. По существующему закреплённому SSH-ключу вызывается единственная root-owned команда `/usr/local/sbin/ege-blizko-lab-release <SHA>` (после однократной настройки на VPS).
5. Помощник разрешает изменять только файлы лаборатории и экзаменационных банков из явного белого списка. **Ни git reset, ни git checkout, ни очистка рабочей папки не используются.**
6. Проверка применимости патча, копии каждого затрагиваемого файла, проверка Python, перезапуск только `ege-blizko`, запросы `/health` и `/lab-app`. При ошибке — автоматическое восстановление скопированных файлов и повторный запуск службы.
7. Выпуски с изменениями БД или других ботов этот механизм не принимает. Данные учеников он не удаляет и не мигрирует. Для изменений схемы БД нужен отдельный план и копия SQLite.

## Почему нужен первый ручной шаг

На сервере работает `hotfix/ege-middle-salts-66-facts-20261007` с незакоммиченными изменениями. Исправление Cu(OH)₂/Fe(OH)₂ уже применено вручную; заменять всё дерево на GitHub-ветку опасно. Поэтому сервер хранит **отдельный SHA последней успешно применённой версии лаборатории** и применяет только разницу между проверенными релизами.

Базовый SHA: `9eddd2528e8e5a163369f09177573af3015b569d`. При однократном запуске `--bootstrap` сервер убеждается, что уже видит анимацию студенистых осадков, и сохраняет этот SHA. Этот шаг не перезапускает службу и не переключает Git-ветку.

## Однократная установка (только после отдельного одобрения)

Из учётной записи root на Timeweb:

- Скачать скрипт `deploy/ege-blizko-lab-release` по **ссылке с неизменным commit SHA** после ревью.
- Проверить `bash -n` и контрольную сумму; установить root-owned копию с режимом `0755` в `/usr/local/sbin/ege-blizko-lab-release`.
- Проверить текущие SSH/права пользователя `ege-deploy`. В отдельный `/etc/sudoers.d/ege-blizko-lab-release` добавить узкое `NOPASSWD`-разрешение ТОЛЬКО на этот защищённый helper; проверить `visudo -cf`.
- Выполнить `/usr/local/sbin/ege-blizko-lab-release --bootstrap`, дождаться `LAB_BOOTSTRAP_OK`.
- Только после проверки и согласования объединить PR с workflow в `main`.

Пароли, приватные ключи и `.env` в чат не отправлять.

## Процесс каждого последующего выпуска

1. Разработчик готовит изменения на `release/ege-lab` и смотрит зелёный `ege-lab-ci.yml`.
2. Владелица подтверждает публикацию из интерфейса GitHub Actions: `ЕГЭ БЛИЗКО — ручной выпуск лаборатории` → `Run workflow` на `main`, точный SHA, `DEPLOY_LAB_ONLY`. Если GitHub Environment настроен на отдельное одобрение, подтвердить также там.
3. После успешного ответа `LAB_RELEASE_OK` можно открыть Telegram и проверить визуальный результат. При несовместимости патча выпуск остановится и работающая версия останется на месте.

## Ограничения

- Автоматизированные тесты не заменяют визуальное испытание химических эффектов и ручную проверку новых химических фактов.
- Прямого удалённого SSH-инструмента в этом чате нет. Пользователю потребуется **одна первоначальная настройка**, а для следующих выпусков — подтверждение в GitHub.
- Другие сервисы (ПРЕПАДМИН, самостоятельная LMS и личный медицинский бот) не входят в разрешённый набор файлов и никогда не перезапускаются этим helper.
