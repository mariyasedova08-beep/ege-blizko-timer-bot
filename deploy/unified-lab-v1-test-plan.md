# ЕГЭ БЛИЗКО — объединение лаборатории v1 (10.10.2026)

## Цель
Одна существующая лаборатория `/lab-app` с исходной химической базой. Отдельного `/lab-preview-20261010` в новой ветке нет. Бот ПРЕПОДМИН и медицинский бот не затрагивать.

## Реализовано в ветке (не в рабочем релизе)
- Переключатель 7 тем: привычная «Тёплая осень» + 6 утверждённых ярких вариантов.
- Выбор темы сохраняется только локально в браузере Telegram/WebApp; не в БД ученика.
- Новая вкладка «Пошаговый практикум» внутри существующего `/lab-app`.
- Четыре проверенных примера: CuSO₄/NaOH, FeCl₃/NaOH, AgNO₃/NaCl, Na₂CO₃/HCl.
- Этапы: реактивы → прогноз признака → наблюдение → модель ионов и проверенные уравнения.
- Молекулярные уравнения и признаки читаются из действующей базы реакций. Ионные схемы разрешены только для вручную проверенных примеров.
- Пока НЕ добавлены №30 и автоматическая проверка ионных уравнений, поскольку нужен отдельный химический банк и валидация.
- Результаты практикума не записываются в статистику; существующие таблицы и методы API не изменены.

## Проверки перед развёртыванием
1. Сверить активную GitHub-ветку и текущий маркер `deploy/release.ref`.
2. Резервная копия SQLite с `PRAGMA quick_check`; резервная копия файлов приложения уже создана пользователем 10.10.2026.
3. Не использовать `git reset --hard` на сервере при наличии непрослеживаемых файлов `data/`, `timeweb_runner.py` и `runtime-vars.json`.
4. Синтаксис Python: `git show FETCH_HEAD:ege_lab_webapp.py > /tmp/ege_lab_unified_v1.py`; `python3 -m py_compile /tmp/ege_lab_unified_v1.py`.
5. Провести тест с конкретными реагентами: CuSO₄+NaOH → голубой Cu(OH)₂; FeCl₃+NaOH → бурый Fe(OH)₃; AgNO₃+NaCl → белый AgCl; Na₂CO₃+HCl → CO₂.
6. Проверить прежний свободный опыт (с цветами, газом, осадками), ОГЭ №12, №17, №23 (порядок склянок), ЕГЭ №6, №24, признаки, историю и статистику.
7. Проверить темы и сохранение после закрытия и открытия Telegram WebApp, мобильный интерфейс и отсутствие утечки ответов.
8. Проверить `/health` и Telegram админ- и ученический кабинеты.
9. Только после одобрения учителя выпускать код в рабочую ветку и обновлять release-маркер по существующей процедуре autodeploy (с откатом при ошибке).

## Откат
Проверять состояние `systemctl status ege-blizko` и `/health`. На случай неполадок вернуть предыдущий commit приложения штатной guarded deploy-процедурой или из ранее сохранённой резервной копии; не перезаписывать SQLite новыми/старыми данными без проверки.
