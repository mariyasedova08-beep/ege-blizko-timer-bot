Статус: **только draft PR, не устанавливать и не активировать автоматически**.

## Уже подтверждено пользователем (22.10.2026)

- Приватный Timeweb S3 бакет: prepodmin-backups-2026.
- Доступ отдельного пользователя prepodmin-restic.
- Restic 0.16.4 на Ubuntu 24.04.5 LTS.
- Секреты S3 и пароль Restic хранятся только в /etc/prepodmin/restic с root-only правами; пользователь подтвердил копию пароля вне VPS.
- Тест Restic -> S3 -> восстановление вымышленного файла -> restic check завершился успешно. **Реальная база и ученические файлы пока не копировались**.
- Существующий prepodmin-backup.timer делает локальные SQLite snapshots. Этот timer нельзя менять.
- ЕГЭ БЛИЗКО и другие работающие приложения не трогать.

## Что подготовлено

prepare_offsite_bundle.py: читает действующую SQLite через online backup API; проверяет PRAGMA integrity_check; копирует/связывает только сохранённые файлы из teacher_webapp_homework_files с соответствующими их именами и размерами. Создаёт manifest.json с SHA256 базы и каждого вложения. Режим verify валидирует восстановленный комплект. Если таблицы файлов ещё нет, сохраняет базу с пустой папкой вложений — это ожидаемо для текущей версии.

offsite_backup.sh: только root-owned установленная копия, без SSH и перезапуска ботов. Проверяет конфигурацию, права, наличие обоих сервисов, блокировку параллельного запуска. Формирует единый закрытый временный комплект и отправляет его как один зашифрованный снимок Restic с тегом prepodmin-offsite. Временная незашифрованная копия удаляется при выходе. Ошибки не выводят файлы и секреты.

prepodmin-offsite-backup.service + .timer: отдельная systemd единица, один раз ежедневно **в 02:45 UTC ± 10 минут**, Persistent=true. Локальный prepodmin-backup.timer (01:30 UTC) остаётся как был. **Никаких push-trigger и автопубликаций**.

## Требуемая ручная установка — ТОЛЬКО ПОСЛЕ ДОПОЛНИТЕЛЬНОГО РАЗРЕШЕНИЯ

1. Сделать ревью PR, проверить успешное CI и корректность root-owned install. Никогда не запускать скрипты от root прямо из mutable checkout /opt/bots/prepodmin/current.
2. После отдельного согласия создать root:root 0700 каталог /usr/local/lib/prepodmin-offsite и /var/backups/prepodmin/offsite-staging.
3. Скопировать проверенные Python и Bash файлы в root-owned каталог с режимом 0500; Bash установить под именем offsite_backup.sh. systemd .service и .timer — в /etc/systemd/system, root:root 0644.
4. Сначала запустить одиночную ручную копию и проверить метку PREPODMIN_OFFSITE_BACKUP_OK. **Этот запуск отправит настоящую приватную SQLite базу и, если есть, реальные файлы в зашифрованном виде в S3**. Требуется отдельное явное разрешение.
5. Из S3 восстановить последнюю помеченную копию во временный **изолированный** root-only каталог. Проверить prepare_offsite_bundle.py verify на восстановленном bundle, затем удалить только временный каталог. Никогда не восстанавливать поверх реальной БД.
6. Только после подтверждённого полного восстановления включить отдельный prepodmin-offsite-backup.timer. Проверить календарь таймера, наличие двух живых ботов, отслеживание ошибок и вместимость S3.
7. Никаких restic forget/prune/удаления, пока не согласована политика хранения и удаления работ несовершеннолетних.
8. Уязвимость инфраструктуры: S3 и VPS обслуживаются у одного облачного провайдера/в одном аккаунте. Шифрование защищает содержимое, но не от удаления всех данных при компрометации аккаунта. После внедрения предусмотреть отдельную независимую копию/неизменяемые версии, мониторинг и периодические проверки восстановления.
