# ПРЕПАДМИН — сдача ДЗ (проект безопасного выпуска)

## Согласованные виды заданий

- Отметка выполнения (self): тест, тренажёр, устное упражнение. Ученик
  нажимает «Я выполнил(а)»; преподаватель видит происхождение отметки.
  Это НЕ подтверждение проверки правильности решения.
- Письменная работа (attachment): ученик загружает JPG/PNG/PDF и нажимает
  «Отправить на проверку». Преподаватель открывает файлы, принимает
  работу или возвращает с обязательным текстовым замечанием.
  Повторная сдача создаёт отдельную попытку, не стирая предыдущую.

Статусы: Не сдано → Черновик → На проверке → На доработке / Проверено.
Для письменного ДЗ статус выполнения в действующей таблице остаётся
pending до принятия учителем. После принятия он становится done.

## Совместимость и ограничения

Существующие аккаунты, оплаты, расписание и Telegram-сообщения сохраняются.
Старые ДЗ без строки режима читаются как self, старые отметки без происхождения
остаются «Отмечено выполненным». Новые таблицы создаются аддитивно.

Файлы не хранятся в SQLite, Git или публичном каталоге и не принадлежат
боту ЕГЭ БЛИЗКО. Разрешены JPEG, PNG и PDF до 8 MiB каждый,
до пяти файлов на попытку, до 20 попыток, квота 2 GiB на преподавателя.
Скачивание учителем по 15-минутному подписанному URL без передачи прав
другим пользователям. Эти URL нельзя логировать или пересылать.

## ОБЯЗАТЕЛЬНО перед Timeweb: не развёртывать автоматически

По умолчанию TEACHER_PRODUCT_HOMEWORK_UPLOADS_ENABLED выключен.
При выключенном режиме письменные ДЗ выдавать и загружать нельзя.

1. Отдельно согласовать объединение PR и, позднее, установку релиза.
   Проверить изолированные тесты и сделать проверяемый бэкап SQLite.
2. Создать приватный каталог вне checkout, например
   /opt/bots/prepodmin/data/homework_uploads, права 0700, владелец
   prepodmin. Задать TEACHER_PRODUCT_HOMEWORK_UPLOAD_DIR с абсолютным
   путём; файлы создаются с правами 0600.
3. Настроить шифрованные независимые резервные копии каталога и БД
   за пределами VPS, проверить восстановление одной попытки ДЗ.
   Обычный снимок SQLite НЕ содержит файлы.
4. Вручную сохранить исходный HTTPS-vhost ПРЕПАДМИНА и сравнить
   с шаблоном deployment/prepodmin/nginx-https.conf: отдельный маршрут
   upload с ограничением 9m/90 секунд и маршрут file с access_log off.
   Провести nginx -t и после разрешения graceful reload. GitHub Actions
   НЕ устанавливает и не перезагружает Nginx.
5. Согласовать обработку работ несовершеннолетних, сроки хранения,
   шифрование и доступ, мониторинг диска и квот 80/95%.
6. На тестовой группе вручную проверить настоящий JPG, PNG и PDF,
   блокировку чужой группы, срок токена, Range HTTP 206,
   отправку, возврат, повторную сдачу, принятие, восстановление файлов,
   действующие оплаты/уведомления и работу ЕГЭ БЛИЗКО.
7. Только после этого включить флаг на Timeweb. На ошибке — отключить
   флаг, вернуть код назад, не удаляя ни БД, ни накопленные работы.

## Вне первого безопасного выпуска

Редактор стилусом, видео/архивы, автоматическая проверка внешних тестов
и автоматическое удаление старых работ потребуют отдельных решений.
Данный документ НЕ разрешает публикацию или изменение сервера.
