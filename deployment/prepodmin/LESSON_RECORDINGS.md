# ПРЕПАДМИН: записи уроков (черновик, НЕ развёртывать автоматически)

Этот модуль **не относится к ЕГЭ БЛИЗКО**. Создаёт два независимых
поля у конкретного занятия группы: HTTPS-ссылка на запись и прикреплённый MP4.

## Что реализовано

- Ссылка и MP4 могут существовать одновременно.
- MP4 до **200 MiB** загружается потоком в отдельный приватный каталог.
- Тема/запись привязаны к \`schedule_slot_id + occurrence_key\`, а не к дате
  переноса, поэтому остаются у конкретного занятия.
- Вкладка показывает будущие уроки и последние 31 день прошедших занятий
  (максимум 12 строк); запись можно прикрепить после состоявшегося урока.
- Доступ к файлу пока **только преподавателю**, после проверки его Telegram
  initData или подписанной ссылки входа. Для воспроизведения выдаётся
  HMAC-подписанный URL сроком 1 час; доступ по нему временно может получить
  любой обладатель этого URL. Не пересылать его.
- Ученикам **ничего автоматически не рассылается**. Отдельное разрешение
  на ученический доступ и согласия на видеозапись — другая задача.
- Ссылка на внешнее хранилище может иметь собственные, не контролируемые
  ПРЕПАДМИНОМ настройки доступа. Вкладка не делает её публичной сама.

## Где физически хранятся файлы

По умолчанию рядом с базой SQLite, вне Git:
\`/opt/bots/prepodmin/data/lesson_recordings/\`.

Каталог имеет разрешения 0700, новые файлы — 0600. Путь также можно
настроить через \`TEACHER_PRODUCT_RECORDINGS_DIR\` только в защищённом
окружении. Не добавлять файлы в репозиторий или общую директорию ЕГЭ БЛИЗКО.

**Важное ограничение:** штатный резервный снимок ПРЕПАДМИНА копирует
SQLite, но **НЕ копирует MP4**. Для запуска реальной функции обязательно
заранее настроить и проверить отдельное шифрованное резервное копирование
каталога записей вне VPS, с восстановлением одного тестового видео.
Не считать одну копию SQLite резервной копией записей. Проверить объём
диска/квоты до включения загрузки и при необходимости ограничить число файлов.

## ОБЯЗАТЕЛЬНО перед запуском на Timeweb

1. После отдельного согласования пройти draft PR → CI → merge → post-merge CI.
2. До установки подтвердить бэкап текущей SQLite, оставить сервис
   \`ege-blizko\` неизменным.
3. **Ручной review конфигурации Nginx:** текущий активный HTTPS-конфиг
   ПРЕПАДМИНА имеет общий \`client_max_body_size 64k\`, поэтому без
   отдельного \`location = /api/teacher/recording/upload\` загрузка MP4
   вернёт HTTP 413. Пример *только для ПРЕПАДМИНА* подготовлен в
   \`deployment/prepodmin/nginx-https.conf\`; GitHub protected deploy
   **НЕ устанавливает и НЕ перезагружает Nginx**. Перед ручной установкой
   сохранить копию активного vhost, сравнить её с образцом, проверить
   \`nginx -t\`, сделать graceful reload только после одобрения.
   Не редактировать конфиг vhost ЕГЭ.
4. Закрыть логи запросов к \`/api/teacher/recording/file/\` — адреса
   содержат временный подписанный токен, их нельзя писать в access.log.
5. Убедиться, что только пользователь Linux \`prepodmin\` может читать
   каталог записей и что он расположен вне \`/opt/bots/prepodmin/current\`.
6. Проверить в отдельном тестовом сценарии загрузку небольшого настоящего
   MP4, выдачу HMAC ticket, воспроизведение частями (HTTP 206), очистку
   и защиту от доступа другого преподавателя.
7. Проверить сохранение настоящих записей и их доступность после обычного
   обновления ПРЕПАДМИНА; затем настроить мониторинг места на диске.

Эта документация НЕ является разрешением на Nginx reload,
merge или развёртывание. Всё — только после отдельного «да» владельца.
